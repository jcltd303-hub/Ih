# Production Security Verification Baseline — 2026-09-17

## Scope

This baseline gates deployment while the production settlement hardening tranche is implemented.

Required checks on a fresh checkout:

```text
npm ci
npm run typecheck
npm run test:ci
npm run build
npm run functions:build
```

The GitHub Actions deployment workflow runs these checks in a dedicated `verify` job. Production deployment then requires the Firebase backend deployment job to succeed before GitHub Pages can deploy.

## Evidence

CI is the source of truth for repository command results. Production deployment evidence is the successful `firebase-deploy` job followed by the dependent Pages build/deploy jobs. Repository configuration alone does not prove that the Firebase credential is configured or that a production deployment has occurred.

## Production deployment contract

The workflow deploys the Firebase Functions plus Firestore and Realtime Database security rules to the configured `fish-frenzy-mobile` Firebase project. The deployment job runs only after all verification checks pass and is protected by the `firebase-production` environment.

The GitHub Pages build explicitly depends on `firebase-deploy`, so a missing credential or failed backend deployment cannot result in a new frontend release being published as though the hardened backend were live.

## Release gate

Deployment must remain blocked until the following are demonstrated by code, automated tests, and deployment evidence:

1. Active server seeds are not readable by clients.
2. Payout-relevant target, fish tier, skin bonus, kill, and boss progression facts are server-authoritative.
3. Duplicate/retried requests cannot create duplicate financial effects.
4. Wallet, settlement, request-idempotency, target-dedupe, boss progression, and telemetry writes remain transactionally consistent.
5. Frontend and Functions verification gates pass.
6. The hardened Firebase Functions and security rules are successfully deployed before the matching frontend release.
